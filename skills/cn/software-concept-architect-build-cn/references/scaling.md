# 规模化：分组与拆包

焦点：怎样改善导航、构建或团队分治而保持概念边界？仅出现这些痛点时使用；十余个概念是线索，不是强制门槛。

**分组** 是工程组织，不是概念或新的架构层；概念互不引用的规则对组内外均成立，业务协调仍经 syncs。

| 决策 | 依据与约束 |
| --- | --- |
| 划组 | 结合产品依赖聚类、共同参与 flow 的程度及团队所有权；命名仅作参考，独立交付仍需验证闭包、入口和剩余规则 |
| 构建边界 | 默认 `concepts/<组>/<概念>/`，保留构建单元；确有构建/团队需要再拆 workspace 或父 POM，并重新配置已有边界检查 |
| sync 包 | 按 flow 职责群拆包，共享规则身份唯一；跨组 flow 归外部入口所属组，不建无职责的公共组；sync 可引用任意组概念，组合根仍统一 |
| 规格 | CONCEPT 随模块，每 sync 包一份 SYNCS；更新 PRD 索引及派生同步图，产品依赖仍以总体 PRD 为准 |

完成时确认没有“同组可互引”或新增“组间业务接口”；所有跨概念策略仍可在 syncs 定位，分组未改变模型行为。
