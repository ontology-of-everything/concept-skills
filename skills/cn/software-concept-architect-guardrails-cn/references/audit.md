# 规格覆盖审计（audit）

焦点：哪些实际行为边界已有有效规格，哪些需要补齐？**覆盖** 是规格对已识别模块的描述范围，不表示模型适切或实现正确。本模式只读，限定路径则外部引用单列。

## 识别与分类

1. 查 CONCEPT/PIPELINE/SYNCS 及 PRD 暂存索引，记录名称、路径和实际管辖范围。分别检查四节、data boundary、app/include/sync；旧 wyx 格式标待迁移，不算有效覆盖。
2. 用源码清单定位候选，跳过依赖、生成/构建产物及纯测试/类型/配置目录；文件数和目录名仅作搜索线索，单文件核心模块也要查。祖先规格是否覆盖须读内容。
3. 根据用途、公开动作、状态所有权和生命周期分类：

| 事实支持的判断 | 类型 / 下一步 |
| --- | --- |
| 独立目的、完整行为和可解释状态 | concept `<路径>` |
| 可区分的转换阶段和质量约束 | pipeline `<路径>` |
| 请求、事件或任务协调概念动作 | sync `<路径>` |
| 仅类型、工具或框架胶水 | 支撑代码，说明跳过理由 |
| 旧格式规格 | 按入口规则迁移 |

聚合、多个 import 或基础设施身份均不足以决定分类；API 程序员也是用户。概念间直接调用另列耦合证据，公开 API 不使互调满足独立性。

## 计划与完成条件

读真实代码依赖决定回填顺序：先被依赖者，再管道/协调；循环以强连通组处理并标边界问题。代码依赖只用于回填排序，不推出产品依赖。

报告已有规格及有效范围、候选/跳过理由及位置、待迁移项、按依赖分批的模式命令；同批按路径排序。未完整枚举分母不报覆盖百分比。

无缺口只表示本次覆盖未发现遗漏。新鲜度交 drift，派生图交 map，设计适切性和全面符合性交 software-concept-architect-review-cn；写入须已有相应授权。
