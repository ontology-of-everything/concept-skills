# 文件编排：CONCEPT.md 与 SYNCS.md

先读 [规格契约与模板](spec-format.md)；本文只规定确认模型如何落盘，不重新定义语法。对照见 [订位例](example-reserving.md)。

| 内容 | 权威位置 | 转录要求 |
| --- | --- | --- |
| 应用目的、场景、Misfits | 总体 PRD | 保存概念/sync 依据及跨概念前提；目的缺失标未决，不从图推导 |
| 单个概念 | 模块旁 CONCEPT.md；未建模块时暂存 docs/prd/concepts/ | 转录四个核心节、已声明 queries 与 notes；实际类型实例化归 SYNCS |
| 应用组合 | syncs 包的 SYNCS.md；暂存 docs/prd/SYNCS.md | 转录期单文件，app/include 后按 `// flow:` 组织规则；外部入口也须有签名来源 |
| 验收 | 总体 PRD 的验收表或现有验收文件 | 每条链接源 OP、动作 case、不变量或应用场景，不把验收加入概念核心语法 |
| 图、依赖、排除与未决 | 总体 PRD | 同步图由规则派生，产品依赖有独立需求依据；SYNCS 不重复放图 |

规格格式可以有意省略无关细节；已确认的签名、结果、状态含义不能遗漏。引用的动作、query 和类型应逐项可定位；零概念参数不强加 `[]`，零动作返回显式为 `=> []`。

已存在文件按授权最小更新，保留 notes 与人工内容；旧方言按共享契约兼容读取，整份迁移时核对成功/错误、关联与状态效果，不能把歧义自动补成需求。实现期暂存迁移、SYNCS 随职责群拆包后更新索引，仍每个元素一处权威。
