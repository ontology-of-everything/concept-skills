# 图解软件概念

## 目标

用有源码依据的图解说明软件概念。仅在用户明确要求本技能时运行。
围绕读者问题和项目场景展开，先用例子解释陌生术语，再给名称。

## 原则

检查相关入口、状态、动作、调用方、界面查询、配置、测试与失败路径，注明文件、符号和当前行号。
文档说明意图，代码说明实现，类或文件不自动成为概念。区分冲突、推断与未知。没有源码就只解释已有设计。

选择最小必要视图，统一术语。教学顺序与模拟不证明执行顺序、事务或运行行为。
现状与建议分开，只报告实际执行的检查和预览。

## 概念

概念通过状态与动作提供价值，运作原理 OP 说明典型行为如何产生有用结果，同步规则协调独立概念。
状态关系、类型绑定、实例、产品依赖与运行时调用须区分。

## 流程

1. 明确目的、场景、读者问题和证据，先追踪相关代码再选图。
2. 读[视图与记法](references/views.md)。先总览，再沿场景展开必要的状态、规则、界面映射或实现。
3. 图与因果说明及源码配对，细节能回到总览定位。
4. 制作 HTML、交互或课程前读[设计语言](references/design-system.md)，复用 CSS 与 JavaScript。
   修改建议附依据、收益和代价。
5. 对照源码与概念判据，复核解释和建议。

## 完成条件

读者能定位场景、跟随行为并检查证据。说明省略与未知，检查作品导航、选择、对比、重置、键盘和窄屏布局。
重置只恢复模拟状态。

课程交付为已组装的离线目录，复用样式与脚本，章节独立维护，资源保存在本地。
无需远程资源、模块拉取、安装或服务器即可打开。实际打开结果并检查。
