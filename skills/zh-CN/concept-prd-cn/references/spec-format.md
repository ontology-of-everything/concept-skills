# 概念与同步规格契约

编写或核对 CONCEPT、SYNCS 时使用。格式改写自 [WYSIWID v1 第 4 至 6 节](https://arxiv.org/html/2508.14511v1#S4)。
Markdown 标题、requires/ensures、queries 和 app 声明是本仓约定，不是引擎语法。

## 保持概念行为

同步可以限制行为，但每个概念的动作、状态与输出序列仍须符合自身契约。
应用限制写在 SYNCS，前置条件、不变量、效果与结果分支归概念。需要新行为时先修订并确认契约。
合法限制也可能使目的落空，因此还要检查有用结果能否达成。

## CONCEPT

新规格按以下顺序编写，未确认行为保留未决。

```markdown
# concept Name [T]

## purpose
<一个可评价的需要>

## state
items: set Item
owner: Item -> T
<声明 Item 为本概念的身份类型；说明关系的基数、初态及必要不变量>

## actions
act [item: Item; owner: T] => [item: Item]
  requires <该成功 case 的适用条件>
  ensures <状态变化、输出值与未改变部分>
act [item: Item; owner: T] => [error: E]
  requires <该错误 case 的适用条件；声明 E 的含义>
  ensures <错误值及状态后果>

## operational principle
after <条件及已声明动作的输入 => 输出>
then <后续动作/观察及可观察结果；如何兑现 purpose>
```

| 要素 | 核对要求 |
| --- | --- |
| 类型 | 外部身份是不假定字段的类型参数。定义局部类型，具体类型在 SYNCS 实例化。 |
| 目的 | 一个可评价的需要。 |
| 状态 | 声明基数、初态与不变量。`A -> B` 本身不表示总函数或唯一性。 |
| 动作 | 输入输出具名。无输入写 `[]`，无返回写 `=> []`。每个分支写条件、效果与输出。 |
| OP | 用已声明动作说明有用结果，不穷举全部行为。 |

字段名参与匹配。成功与拒绝须能区分；条件重叠且效果不同时，说明选择规则或标未决。
失败不默认保持状态，成功不默认改状态，只读动作仍产生完成事件。
保留影响协调的细节，实现前消除会改变行为的歧义，不为填模板补造错误、权限或功能。

## 状态与查询

应用可按公开接口查询抽象状态，包括跨概念 join，不开放私有表或内部实现。概念之间不互读、不互调。
where 默认读取声明关系，可在可选的 queries 节映射为 API：

```text
_owners [item: Item] => [owner: T]
  returns owner 关系中匹配 item 的绑定；无匹配为零行
```

声明输入、结果、零/一/多行含义及对应关系。查询只读、不产生完成事件，不是第五个核心节。
`Name/_owners: [item: ?item] => [owner: ?owner]` 只用于 where，不能放入 when 或 then。
不为每个字段造 getter，也不把空集改成未声明错误。状态、基数或查询能力未知时保留缺口。

## SYNCS

每个 include 指向可定位的概念规格或明确的外部入口契约，别名、类型与入口签名须有定义。
Requesting/Web 只是选项，定时和消息也须声明根动作。

```text
# app AppName
include Source [Id]
include Target [Id]
include Web

// flow: transfer
sync Transfer
when {
  Web/request: [method: "transfer"] => [request: ?request]
  Source/finish: [] => [item: ?item]
}
where {
  Source: { ?item owner: ?owner }
}
then {
  Target/accept: [item: ?item; owner: ?owner]
}
```

这是记法示例，Source.owner、目标输入与响应义务须对照真实契约。

| 部分 | 含义 |
| --- | --- |
| sync | 应用内唯一、稳定的规则名，对应一项可解释决定。 |
| when | 必填，匹配已完成动作 `Concept/action: [输入] => [输出]`。全部模式须处于同一运行时 flow。 |
| 模式 | 未列字段是通配，`[]` 不表示成功。动作可返回错误时须匹配已证实的判别条件。 |
| where | 可选，读取状态、过滤、计算或产生零组及多组绑定。省略时保留原绑定。 |
| then | 必填，对每组绑定发出调用，具名输入填全，不写输出模式。匹配可省略的字段不表示调用可漏参。 |
| 变量 | `?name` 在规则内同名同值。调用只用常量或已绑定值，同组无隐含顺序，后续输出由另一规则匹配。 |

## 结果与关联

- 已声明 error 与 `valid: false` 等否定值分别匹配。写入前先获得授权，事后拒绝不会撤销完成的写入。
- where 零行不调用，多行展开调用。需要响应时定义零匹配结果。默认取第一个或全部执行都须有契约依据。
- flow 标识根事件及后续，同类动作重复时还须按对象身份配对。request 用于定位响应，`// flow:` 只作文档分组。
- 保留已完成动作，明确响应、重试、补偿或有意忽略及状态后果。动作原子检查不变量，事前查询不能代替它。
- 需要恢复时记录动作身份、flow、规则、因果、绑定与发出调用。核验引擎去重，避免重放再次发出；外部效果另需幂等保障。

## 兼容与核对

兼容 principle、旧顺序、`act (arg: T) : (result: R)`、`Concept.act (...) : (...)` 及 actions 内的 `_` 查询。
语法差异本身不是漂移。新文件用本契约，局部修改保留既有方言，整份迁移须有授权。

迁移前核对输入、输出、成功/错误判别与关联。旧输出省略时，不能改为也会匹配错误的 `=> []`。
旧事务同步与 wyx 边界段单独识别，保留行为与未决，并更新所有引用和图。

依次核对类型、状态/查询、动作结果、匹配分支、查询行数、调用参数与关联响应。
OP 与应用场景分别追溯。跨概念策略归 SYNCS，目的、产品依赖、排除与未决归总体 PRD。
实现时另查并发、恢复与可观察结果。
