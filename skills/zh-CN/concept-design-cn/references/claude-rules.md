# 校准 CLAUDE.md

1. 核对已确认设计契约、实际实现与适用工程约定。
2. 写规则前报告冲突。MUST NOT 把实现现状当契约，也不得改契约迁就缺陷。
3. 使用下方五条规则模板更新 `CLAUDE.md`。每条 MUST 注明依据与检查方式；引用权威定义，不复制正文。
4. 只更新相关规则，保留无关内容；未决事项保持未决。
5. 将更新后的规则与三方逐项核对。报告未解冲突和未执行检查；有证据才声明一致。

## 输出模板

```markdown
1. 开发前核对已确认设计、现有实现与工程约定；发现冲突先报告。
2. 按 CONCEPT.md 实现状态、动作与不变量；禁止概念互调、互读状态。
3. 按 SYNCS.md 实现跨概念协作；代码与规格中的输入、条件、结果必须一致。
4. 行为变更先确认并更新契约，再修改代码与测试；不得改契约掩盖缺陷。
5. 每项约束关联权威定义与检查方式；完成前验证设计、实现和工程约定，未验证不得报通过。
```
