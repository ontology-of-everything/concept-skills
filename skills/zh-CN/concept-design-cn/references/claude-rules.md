用下列短原则替换重复表述，保留无关规则与未决事项。每条关联项目内权威定义和实际检查，不复制规格正文。

```markdown
1. 工程采用 entry/<分组>、usecases/<分组>、modules/<业务名>、bootstrap，按需设应用级 adapters/contracts/infrastructure；业务目录小写单数，业务模块内按 api/application/domain/adapters 分责。设计保留概念与同步术语，显式维护概念到模块、组合与规则到用例实现的映射；命名例外按确认范围记录。
2. 入站适配器建立或传递声明的根动作完成记录及其 flow，直调公开的 <动作>UseCase。用例按 when/where/then 经业务模块 API 执行一条入口同步规则。合并纯转发 Facade。独立规则通过动作完成记录衔接，辅助组件只提供计算或执行机制。
3. 业务模块实现独立概念，独占状态与不变量，禁止业务模块互依、互调、互读；业务访问只用 api，装配用专属入口。application 依赖 api/domain 和内部端口，adapters 实现端口；api/domain 不依赖模块其他层，以上业务层独立于框架。
4. 按 CONCEPT.md/SYNCS.md 实现；行为变更先确认契约。每条同步规则对应一个具名实现，后续规则按各自匹配的完成记录触发。列表与集合按语义用复数。保留规则到实现的映射、持久身份及既有失败与重试语义。
5. 架构检查区分设计与源码路径，覆盖目录、命名、依赖、可见性和规则映射；工程改名核对测试、模块发现、装配配置、文档引用及持久事件类型，按存量与发布状态确定迁移范围。行为测试覆盖契约与执行边界。失败改代码，未验证不报通过。
```
