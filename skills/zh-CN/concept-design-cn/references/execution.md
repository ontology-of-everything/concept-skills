# 执行、恢复与迁移

业务行为按[规格记法](spec-notation.md)定义。本文补充工程保障：实现必须在声明的并发、失败和恢复条件下保持契约。

## 执行约束

概念内要求归 `CONCEPT.md`，跨概念要求归 `SYNCS.md`，按需附注即可。每项要求关联动作或规则，写清**允许的行为、必需结果、成立前提与验收**。只记录适用的完成时点、顺序、关联、重复、失败、时限和恢复策略；未知标 `open`，无关标 `not applicable`。

## 执行检查

- **完成有边界。** 调用请求执行，完成记录保存声明结果，发生记录身份关联两者。参数相同不是同一次执行；异步动作须明确完成时点，受理或入队不等于后续完成。
- **因果可追溯。** flow 包含根发生记录及其后续；`then` 调用与完成沿用该 flow，`when` 只匹配其中的记录。重复尝试还须关联发生记录或因果，明确匹配全部还是某次尝试。持久事实用 `where` 读取，延迟回调用入口与关联协议衔接；`// flow:` 仅为文档标签。
- **结果有策略。** 错误与 `valid: false` 分开匹配，供规则处理的异常映射为声明分支。零绑定不调用，多绑定逐行调用；声明必需的零匹配响应、候选选择、失败处理及循环控制。后续失败保留已有完成记录。
- **检查与效果一致。** 跨信任边界验证输入与身份，格式校验不代替授权。授权须覆盖实际资源与操作，在受保护效果前检查并保持有效；动作原子检查不变量。
- **触发可去重。** 按发生记录组合与绑定行确定身份，原子认领后发出调用，保留合法重复、防止禁止的重复。查询稍后才有效时显式触发重求值，并声明新绑定能否产生新调用。

在组合中用具名函数或对象实现规则。普通调用、监听器和 Promise 链遵守相同原则；无重启恢复要求时可用内存记录，否则执行下述恢复协议。

## 原子性与恢复

数据库事务只覆盖参与事务的存储，不能使外部效果原子化。跨概念事务须同时满足契约允许和存储可参与两个条件。

要求重启恢复时，逐一关闭以下崩溃窗口：

| 崩溃窗口 | 必需保障 |
| --- | --- |
| 状态已提交，完成记录未保存 | 状态与 completion/outbox 原子提交，或显式对账，防止必需工作静默丢失。 |
| 触发已认领，调用未分发 | 原子保存认领与待执行调用，保留完成身份、flow、规则身份/版本、绑定和原因。 |
| 目标已提交，确认未返回 | 用稳定调用身份和接收方去重，或声明的对账策略；已处理标记本身不保证效果恰好一次。 |
| 外部效果已发生，后续失败 | 对外部效果执行同等幂等检查，保留已完成动作；补偿不必恢复原状态。 |

重试须有上限或受控继续策略，并暴露耗尽。[登录案例](spec-examples.md#外部身份登录)展示了部分完成：错误响应不会撤销已有身份或资料更新。

## 兼容

状态、身份、接口或规则变更前，检查存量数据、已部署调用方、待执行调用和历史完成记录，确定所需迁移、回填、新旧兼容及回滚或前滚。若重放会重新解释旧记录，须给规则分版本或排空受影响工作。代码改名不改变存储身份；仅移动代码时先核实是否需要迁移。

## 检查

按适用范围验证：成功/拒绝、零/多绑定、同值重复、跨 flow 记录、并发重复求值、查询与写入间状态变化、上述崩溃窗口、重投、在途迁移与重试耗尽。证据须关联实际效果、动作发生、因果来源及对应契约；未执行的检查保持未验证。
