# 决策记录

沿用现有文档或讨论记录，不要求新建文件。
决定或需求需要被引用时采用稳定 ID。

| 记录 | 内容 |
| --- | --- |
| 概念清单 | 名称、目的、OP、熟悉/变体/新概念、可见状态、资格证据 |
| 场景 | 受益者、现状/必需行为、约束、可观察结果、概念/规则、反例 |
| 组合 | 实例、绑定、入口、规则、同步图、场景关联 |
| 产品子集 | 目的、有需求依据的依赖、入口、剩余规则、资源 |
| 排除与缺口 | 条目、原因、影响、受阻工作 |

关键取舍采用以下形状，不逐句填表：

```yaml
id: D1
status: proposed # confirmed | proposed | inferred | open
claim: 一项行为要求或边界选择。
basis: 需求或已读证据；已确认决定注明谁确认了什么、出处在哪。
alternative: 备选，适用时包含不改。
counterexample: 能推翻主张的场景，或明确的未决问题。
acceptance:
  setup: 必需初始条件。
  stimulus: 动作或事件。
  observe: 可观察结果及有要求的失败或时限边界。
```

未知项直接标明，不为填满模板补造内容。
每项必需结果 MUST 关联动作、OP 或规则及可观察验收。
替代已确认决定时，注明旧版本并重查相关规则、子集与验收。
