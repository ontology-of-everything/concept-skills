# 设计产物

先确认概念清单、应用场景和产品子集，再写入已确认记录。待确认项另列，沿用已有确认。

## 对齐

| 部分 | 必要内容 |
| --- | --- |
| 概念清单 | 名称、目的、运作原理、熟悉/变体/新、用户可见状态、确认状态 |
| 应用场景 | 受益者、目的、现状与期望、约束、可观察条件和结果、参与概念与规则、反例 |
| 依赖与子集 | 有需求依据的依赖、讲解顺序、可行子集、最小产品、入口、剩余规则与外部资源 |

逐项区分证据、推断与未决前提，标明已确认或待确认。
`A → B` 表示当前产品纳入 A 需要 B，不表示代码依赖。

## 已确认记录

| 部分 | 必要内容 |
| --- | --- |
| Concepts | 目的、状态、动作、运作原理，可选 queries/notes；八项资格结论及依据 |
| Synchronizations | app/include/sync，按入口或职责分组，关联已确认场景 |
| 同步图 | 规则节点、共同成立的 when 输入、then 目标及单独标明的 where 读取 |
| 排除与未决 | 候选/动作/前提、决定、来源、影响及阻塞的工作 |

写法见[规格契约](spec-format.md)。说明契约如何支持运作原理、结果如何兑现目的，缺口直接列出。
同步图与产品依赖分别表达。
