# 概念组合

记法与执行语义采用[规格记法](spec-notation.md)。

| 场景证据 | 可选修改 |
| --- | --- |
| 缺少必需联动 | 收紧同步。 |
| 自动化夺走必需手动控制 | 放松同步，或改为可配置。 |
| 组合改变概念目的 | 重查边界与契约。 |

按具体场景与需求判断缺失联动或失去选择，不能仅凭规则数量或流程长度判定。

access、notify 等协调动作仍须有契约。
日志与队列须有独立目的与完整行为，才可能成为概念。

## 同步图

每规则一个节点，保留共同成立的全部 `when` 输入、全部 `then` 目标及独立的 `where` 读取。
简化箭头 MUST 保留规则名与合取关系。
循环须能终止或受控持续运行。
工程截断 MUST 可观察。

## 产品子集

内在依赖嵌入另一概念定义，改用类型参数或外部协调。
外在依赖来自产品需求：`A → B` 表示当前产品纳入 A 需要 B。
代码耦合或类型实例化本身不能证明它。
产品依赖与同步图分别表达。

每个子集 MUST 具备目的、依赖闭包、入口、有效的剩余规则与资源。
产品依赖环须一起纳入或排除。
