# 规格记法

**默认采用[阅读版](spec-reading.md)**，面向产品讨论与验收；需要实现或精确核对时，按需展开本文件的记法。两版表达同一规格，不独立维护不同需求。

概念规格写在 `CONCEPT.md`，同步规格写在 `SYNCS.md`。用自然语言说明行为，保留具名参数、条件与结果；尚未确定的内容明确标为未决。

## CONCEPT

```text
concept Name [Type]

purpose
  <为什么需要这项功能>

principle
  <说明行为如何兑现目的的代表性场景>

state
  a set of Items with
    <与其他对象或简单值的关系>

actions
  action (input: Input): (result: Result)
    requires <动作发生的条件>
    ensures <前后状态、输入与结果之间的约束>

  _query (input: Input): (result: Result)
    returns <满足查询条件的绑定>
```

**类型参数**表示具有身份的对象，不引入其他概念的结构。

**状态是关系。** `a set of Items with ...` 按对象类型组织关系，不表示类或复合对象。说明必要的初态与关系约束。

**动作按前后条件说明。** 输入与结果具名；没有结果时省略结果部分。`requires` 不成立，动作不得发生；条件成立不保证动作发生，也不自动规定错误响应。`ensures` 约束前后状态及结果。

**查询只读，返回绑定集合。** 查询列在 `actions` 中，名称以下划线开头。返回零个、一个或多个绑定，取决于查询定义。

**运作原理说明目的如何实现。** 它是代表性场景，不代替全部动作规定。

## SYNCS

先说明参与组合的概念实例及类型对应关系，再逐条定义同步。

```text
sync RuleName
when Source.action (item)
where
  Target._find (item): (target)
then
  Target.apply (target)
```

**规则具名。** 一个名称标识一条因果规则，便于解释与追踪。

**`when` 匹配动作发生。** 写明触发动作及所需参数。参数按名称关联，允许只匹配有关参数；查询不作为触发动作。

**`where` 查询与绑定。** 读取公开状态、检查条件并绑定后续所需变量。同名变量指同一值。

**`then` 发起后续动作。** 参数来自触发模式、查询绑定或明确的常量。对 `where` 产生的每个绑定执行；没有绑定则不执行后续动作。

**协调放在概念之外。** 规则使用概念声明的动作与公开状态，不让概念相互调用。请求可以发生，而所请求的动作未必发生。

## 执行语义

**动作是原子的。** 模型中的动作没有可观察的持续时间；持续活动用开始、结束等动作描述。

**同步是因果规则。** 一个动作发生后，满足条件的后续动作才发生；不隐含整条动作链的事务或回滚。需要先后关系时，通过动作发生建立，不凭书写位置推断。

业务条件直接写入动作或同步。并发、重复、时限与恢复按实际需要记录，工程要求见[执行与恢复](execution.md)。

## 工具检查

`concept-lint` 与关系图工具读取[工具编码](tool-encoding.md)。工具格式是规格的显式编码；转换须保留名称、参数、条件、结果与未决项，不补造需求。本文的原生记法不属于当前解析器的支持范围，不得报告为已通过检查。
