# 工程架构

以下是本技能的工程约定，不是 Jackson 指定的实现。新项目默认多模块单体，同进程装配。
遵循语言原生源码根目录与已确认的构建、持久化技术；目录角色、职责和依赖按本文固定。
仅显式确认的例外可覆盖本布局，须记录适用范围；现状不构成例外，迁移限于授权范围。

## 目录与命名

```text
<应用源码根>/
  entry/<业务模块>/                 # 协议入口与外部适配
  compositions/<业务分组>/
    <BusinessScope>Facade            # 公开业务操作
    <BusinessAction>Synchronization  # 内部同步实现
  concepts/<概念名>/
    api/                             # 公开命令、查询与业务值类型
    application/                     # 动作、查询实现及内部端口
    domain/                          # 状态、不变量、领域行为、仓储契约
    adapters/                        # 端口实现、持久化、内部装配
  bootstrap/                         # 最终装配、受控启动入口
```

- 层名固定为 `entry`、`compositions`、`concepts`、`bootstrap`；概念内按图命名。独立构建可移动源码根，保留角色与边界。
- 业务模块、组合分组、概念目录用小写单数；同一业务范围使用同一词根。组合分组与规格目录同名，不要求入口、组合与概念一一对应。
- Java 包名全小写，复合词连写，如 `operatorsession`；其他语言按原生命名规则编码同一业务名。类型与方法遵循语言惯例。
- 门面用 `<BusinessScope>Facade`，同步用 `<BusinessAction>Synchronization`；不增设 `UseCase` 或 `Mediator` 中间层。函数式实现保持同等角色与可见性。
- 类型的业务主体用单数；列表动作与集合变量按语义用复数，如 `ReadBookingsSynchronization`、`bookings`。REST 路径由接口契约定义。
- 每个概念独占源码包或模块。只建有职责的层，删除范围内空占位包；组合分组内不再套领域分层，不为每条规则拆构建单元。

Java/Spring 显式装配统一命名：概念内用 `concepts/<concept>/adapters/<Concept>Configuration`，组合内用 `compositions/<group>/<BusinessScope>Configuration`，最终装配用 `bootstrap/<Application>Configuration`。按需建立，只构造、注入和连接组件，不执行业务操作或判断。配置值绑定用 `<Capability>Properties`，放在使用方边界，与装配分开；其他语言保持职责一致，采用原生装配方式。

## 分层职责与依赖

业务调用链固定为 `Entry → Facade → Synchronization → 概念 API`。
箭头表示业务调用；适配器通过实现内部端口保持源码依赖向内。Bootstrap 可访问装配入口，不调用同步实现。

| 归属 | 硬约束 |
| --- | --- |
| Entry | Controller、Filter、Job 等按业务模块放置；入站入口负责协议解析、格式校验、可信上下文提取和响应转换；出站适配器实现组合端口。业务操作经 Facade，禁止调用同步或概念动作、查询。通用协议机制留在入口层。 |
| Facade | 公开应用操作，每个操作方法恰好转发一次到所属同步。只持有同步协作者，不判业务条件、开事务、处理失败或调用概念及外部适配器。 |
| Synchronization | 将入口输入接入声明的根动作；按 SYNCS 组织跨概念条件、授权复核、动作顺序、事务与失败策略。仅通过概念 API 和所需端口访问业务能力；实现对组合外部不可见。 |
| 组合辅助组件 | 复用具名计算或执行机制；业务步骤、顺序和分支在同步中明确可见。不得调用同步或 Facade。 |
| Concept | 独占自身状态与不变量。概念之间禁止源码依赖、动作或查询调用、状态读取。外部身份用类型参数或不透明 ID，不携带其他概念的内部结构。 |
| api | 只公开业务契约与值类型，按调用能力分开命令和查询；不依赖概念内部层，不暴露协议、框架或持久化类型。 |
| application | 实现 API，依赖 domain 与内部端口，组织概念内动作和查询；不依赖 adapters。 |
| domain | 拥有状态转换、不变量与聚合仓储契约；不依赖 api、application、adapters 或框架、持久化类型。概念不等于聚合。 |
| adapters | 实现内部端口，容纳 SQL、映射器、数据库记录与内部装配；仓储存取聚合，查询端口读取投影。同一职责只定义一个端口。 |
| Bootstrap | 负责最终构造与装配，可委托模块工厂或配置；业务调用仍经 Facade。测试装配可构造概念及假端口。 |
| 技术库 | 不依赖概念或组合，不隐藏业务状态或协调。 |

概念不依赖 Entry、组合或 Bootstrap。组合不依赖 Entry、Bootstrap 或概念内部，也不得经辅助组件绕过；同步之间禁止互调或回调 Facade。
组合定义自己的端口，由 Entry 适配器实现；概念端口由本概念的 adapters 实现。
Facade 使用普通应用类型，可复用概念 API 值类型；协议类型不得穿透业务契约。
api、application、domain 独立于框架和持久化类型；业务代码不得从容器查找依赖。业务导出与装配入口分开。
组合可保存执行记录，不得复制概念业务事实。共享值类型、数据库设施与迁移必须保持明确归属。

## 同步边界

Composition 是组合层，Synchronization 是其中的规则实现。按业务职责分组，可跨上下文。
默认一条具名规则一个同步实现；独立触发、事务或恢复边界需要拆分时，显式映射。相关操作可共享实现，但每条规则保留独立身份。
类长度与方法数量不决定边界；仅实现复杂时提取辅助组件。

规则通过动作完成记录衔接，不直接互调。按[执行与恢复](execution.md)保持同 flow 匹配、前置条件、因果来源与原子触发认领；事务与恢复按契约适用，不因采用普通调用而省略执行保障。
过程状态出现独立业务目的与生命周期时，重新评估概念边界。

## 规格归属

| 内容 | 权威位置 |
| --- | --- |
| 概念 | 概念模块旁 `CONCEPT.md`；未建模块时用 `docs/prd/concepts/<name>/CONCEPT.md`。 |
| 同步 | `compositions/<group>/` 规则旁 `SYNCS.md`；未建模块时用 `docs/prd/compositions/<group>/SYNCS.md`。 |
| 验收 | 总体 PRD 或已有验收文件，关联契约或场景。 |

总体 PRD 索引全部规格；已确认其他位置保留单一权威来源，未经授权不迁移。
实例身份、类型绑定、共用入口契约各声明一次；重复 include 指向同一声明实例，装配保持该映射。
规则身份在应用内唯一，规格、测试与运行记录保持一致；移动或改名不得改变持久身份。
文档维护规则到实现及入口方法的映射；代码名表达业务含义，注释解释约束与原因，不以规格编号命名。
文件与 `// flow:` 分组不创建运行时 flow，也不要求独立构建。

## 审查与验证

架构检查必须覆盖全部相关源码、构建单元与支持配置，并接入常规检查或 CI：

- 核对目录、单复数、命名、模块发现与规则映射；空匹配、漏模块、未解析依赖是缺口，不是通过。
- 检查实际依赖、可见性与环：概念独立、仅 API 访问、依赖向内、端口归属、装配访问及技术库边界。
- 检查 Facade 每个操作只转发一次，无分支、异常决策或其他调用；同步和辅助组件不越界互调。
- 检查业务契约及概念 api/application/domain 无协议、框架或持久化类型泄漏；核对实际启用的适配器。
- 每条违规报告规则、来源、目标与位置并使检查失败；用隔离反例确认检查能够拒绝违规。

Rust 核对构建图与 crate 内边界；Java 核对子包可见性与实际发现的模块；TypeScript 覆盖别名及仅类型导入。
分别测试概念、组合、协议与装配；条件、事务、失败和并发语义用行为测试验证，静态检查不代替行为证据。
指定产品子集还须检查目的、入口、规则、资源、构建开关与发布归属。
报告反射、动态查找和跨归属 SQL 等检查限制；迁移遵循[执行与恢复](execution.md)。
