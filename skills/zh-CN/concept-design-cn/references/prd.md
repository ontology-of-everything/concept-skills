# 编写 PRD 与规格

转录已确认行为，不重新设计。
保留前提、人工备注、已放弃方案、确认来源，以及目的、OP 与契约之间的论证和缺口。
代码可核实位置和索引事实，代码差异 MUST NOT 产生需求。

1. 读已确认模型与需求出处。
2. 按下表为每个模型元素指定唯一权威位置。
3. 按[规格格式](spec-format.md)写契约与规则。
   保留签名、状态效果、结果分支与关联。
   默认包含[执行约束](spec-format.md#执行约束)，未确认策略保留未决。
4. 从需求、OP、场景与契约导出验收。
   记录出处、前提、触发、可观察结果及有要求的失败或时限边界。
   核对链接、类型与签名，更新索引与图。

| 元素 | 权威位置 |
| --- | --- |
| 应用目的、场景、图、依赖、可行子集、前提、排除、未决 | 总体 PRD |
| 单个概念 | 模块旁 `CONCEPT.md`；模块未建时 `docs/prd/concepts/<name>/CONCEPT.md` |
| 内聚组合分组 | `apps/<app>/src/compositions/<group>/` 规则旁 `SYNCS.md`；模块未建时 `docs/prd/compositions/<group>/SYNCS.md` |
| 验收 | 总体 PRD 或已有验收文件，关联所检查的契约或场景 |

路径为逻辑示意，沿用语言源码根目录和已有分组。
未授权迁移时保留已确认旧位置，包括 `docs/prd/SYNCS.md`。
全部 CONCEPT 与 SYNCS 纳入索引。
每条规则 MUST 只定义一次，保留应用内稳定唯一身份。
应用实例、绑定与共用入口契约声明一次，各分组引用。
重复 include 指向同一实例。
文件及 `// flow:` 分组不创建运行时 flow 身份，也不要求独立构建。

缺失的模型决策交回设计并保留未决，不补造结果。
验收要求与已执行测试的证据分开。
通过[场景索引](examples.md#场景索引)查找完整模型与反例。
