# 概念资格

概念是用户为某个目的理解和使用的功能。状态与动作定义行为，运作原理展示有用结果。逐项检查八项资格。

| 判据 | 问题与示例 |
| --- | --- |
| 面向用户 | 用户体验到什么行为？API 程序员也是用户。 |
| 语义性 | 是否有明确的状态与行为含义？颜色或控件本身不足以成为概念。 |
| 独立性 | 不读另一概念能否理解？评论面向条目身份，无需定义帖子。 |
| 行为性 | 用户能做什么、得到什么？列对象属性还不够。 |
| 目的性 | 是否服务一个有独立价值的需要？某步骤可能属于更大的概念。 |
| 端到端 | 是否达到有用结果？认证须能验证身份，不能只有注册。 |
| 熟悉性 | 用户能否沿用经验？优先熟悉行为或有依据的变体，新颖本身不是缺陷。 |
| 可复用性 | 同一含义能否用于别处？已有复用不代替目的、完整性和独立性。 |

| 候选 | 边界判断 |
| --- | --- |
| 类 | 可以实现概念，类边界本身不能证明概念成立。 |
| 可选功能 | 私密账户可能是关注概念的审批选项。 |
| 用户故事 | 今日出勤录入可能属于考勤，还须检查学期汇总等有用结果。 |
| 微服务 | 部署边界不自动成为概念边界。 |

每项记录证据与结论，通过实际场景解决争议，不凭文件/表数量或实现形式判断。
