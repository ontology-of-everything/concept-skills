# 组合检查

记法、关联和失败语义见[规格契约](spec-format.md)，本页检查设计选择。[订位例](example-reserving.md)展示如何拆规则。

## 选择协调方式

| 现象 | 处理 |
| --- | --- |
| 应发生的联动没有发生 | 收紧同步，补上遗漏规则。 |
| 自动化夺走需要的手动控制 | 放松同步，或改为用户可配置。 |
| 组合改变了概念目的 | 重审概念边界与契约。 |
| 流程参与者较多 | 检查具体场景，不凭长度新增概念。 |

每项决定须有应用目的和场景依据。access、notify 等为协调预留的动作仍须有契约。
日志或队列只有具备独立目的与完整行为时，才可能成为概念。

## 绘图与检查

每条规则保留一个节点、全部 when 条件、then 目标和独立的 where 读取。
简化箭头须保留规则名与合取关系，不表示产品依赖。
循环须能终止或受控持续运行，工程截断须可观察。

## 依赖与子集

内在依赖把另一概念的定义带入本概念，应改用类型参数，或将协调移到同步规则。
外在依赖来自当前产品，`A → B` 表示纳入 A 需要 B，记录在对齐结果与总体 PRD。

代码耦合不能证明产品依赖。子集须满足目的、依赖闭包、入口、剩余规则与资源要求。
产品依赖环中的成员一起纳入或排除，仅分组并不表示可交付。
