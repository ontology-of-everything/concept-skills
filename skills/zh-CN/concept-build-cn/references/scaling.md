# 分组与包

只有导航、构建或归属存在实际问题时才分组，沿用[工程架构](architecture.md)。分组不允许概念互引。

| 决定 | 规则 |
| --- | --- |
| 分组 | 依据产品依赖、共同场景或团队归属，单独核验交付能力。 |
| 构建单元 | 需要时用 modules/concepts/组/概念，每个概念一单元。拆 workspace/父构建须有实际需要，并更新依赖检查。 |
| composition | 默认一个模块内分规则组，职责不同时才拆。规则身份唯一，跨组流程归其外部入口拥有者。 |
| 规格 | CONCEPT 与模块共置，每个 composition 一份 SYNCS，更新 PRD 索引和图，产品依赖留在总体 PRD。 |

分组后核对目的、依赖、入口、规则、资源、构建开关与发布归属。
跨概念策略仍在 composition，server 统一装配。目录嵌套本身不证明模块或子集可交付。
