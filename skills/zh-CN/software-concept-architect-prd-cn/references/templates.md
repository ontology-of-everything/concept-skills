# 规格文件位置

语法见[规格契约](spec-format.md)，转录过程见[订位例](example-reserving.md)。每个模型元素只有一处权威位置。

| 内容 | 位置与关联要求 |
| --- | --- |
| 目的、场景、反例与前提 | 总体 PRD，保存概念和规则的选择依据，缺失目标仍标未决。 |
| 单个概念 | 模块旁的 CONCEPT.md，或暂存 docs/prd/concepts/；保留四个核心节、已声明 queries 和 notes。 |
| 应用组合 | composition 的 SYNCS.md，或暂存 docs/prd/SYNCS.md；包含应用与类型绑定、入口签名，规则按 `// flow:` 分组。 |
| 验收 | 总体 PRD 或现有验收文件，关联 OP、动作分支、不变量或应用场景。 |
| 图、依赖、排除与未决 | 总体 PRD，同步图由规则派生，产品依赖须有需求依据。 |

保留确认过的签名、结果、状态含义和人工备注。引用的类型、动作和查询须可定位。
概念无类型参数时省略 `[]`，动作无返回值时写 `=> []`。

实现期每个概念构建单元一份 CONCEPT，每个 composition 一份 SYNCS，flow 分组不另建规格。
迁移暂存文件或实际拆模块后更新索引。旧格式迁移前先核对结果分支、关联与状态效果，不将歧义补成需求。
