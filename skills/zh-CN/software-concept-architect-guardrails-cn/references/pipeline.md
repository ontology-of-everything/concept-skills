# 数据质量规格

PIPELINE 说明来源、转换、输出、可检查的质量、触发及公开读写边界。跨概念协调仍归 SYNCS。

```markdown
# pipeline: <名称>
## purpose
<输出给谁、满足什么需要>
## sources
- <表/文件/API、关键字段、拥有者、规模或 unbounded>
## stages
### <阶段名> [tool: <项目工具>]
in: <输入及类型>
out: <输出及类型>
<转换逻辑>
quality: <可执行的质量判断>
## outputs
- <格式、关键字段、拥有者、规模>
## invariants
- <全程质量规则及验证方式>
## triggers
- <sync、API、定时或手动入口>
## data boundary
- <源拥有者 → 公开读取接口>
- <输出拥有者 → 公开写入接口>
```

按实际命令、工作流、schema、查询/join 与检查回填，标明数据拥有者或外部来源及公开接口。
跨概念工作放 composition。概念自己的存储适配器可用 SQL，管道不因此获得跨概念私有访问权限。

score 在 [-1, 1] 内可检查，"数据干净"不可检查。行数上限只有契约要求时才成立。
按有意义的转换划阶段，使用实际工具，不把每个小操作都拆成阶段。
记录各阶段输入、输出、失败后果与检查。新流程还须说明追加/刷新和幂等方式，缺失控制标未决，不补造。

所属 PIPELINE 与 CONCEPT 共置，跨概念管道放 composition。
来源、阶段、输出和不变量须对应代码或明确的待实现契约。发现阶段只列候选，纯协调交 sync 模式。
