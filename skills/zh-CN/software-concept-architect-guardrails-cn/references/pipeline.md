# 数据质量规格（pipeline）

焦点：数据怎样转换，哪些质量判断须成立？PIPELINE 是本仓的数据质量契约，补充 Jackson 概念模型；跨概念协调仍由 SYNCS 表达。参数、授权和落位遵循入口。

## 概念与关系

**来源/输出** 是有明确拥有者或外部来源的数据；**阶段** 以可独立核验的输入、转换、输出划分；**不变量** 是可判定的质量命题；**data boundary** 把拥有者与公开读写接口关联。

内部数据通过拥有者的 actions/query 访问；跨概念读写位于组合层，概念内部管道不获得互调许可。自身存储适配器可用 SQL。

## 契约模板

```markdown
# pipeline: <名称>
## purpose
<输出给谁、满足什么需要>
## sources
- <表/文件/API、关键字段、拥有者、规模或 unbounded>
## stages
### <阶段名> [tool: <项目工具>]
in: <输入及类型>
out: <输出及类型>
<转换逻辑>
quality: <可执行的质量判断>
## outputs
- <格式、关键字段、拥有者、规模>
## invariants
- <全程质量规则及验证方式>
## triggers
- <sync、API、定时或手动入口>
## data boundary
- <源拥有者 → 公开读取接口>
- <输出拥有者 → 公开写入接口>
```

例如 `scores in [-1, 1]` 可检查；“数据干净”缺少判断条件。数量关系如 `output.rows <= input.rows` 只有契约确实限制基数时才成立，不能机械套用。

## 执行与完成

回填读真实查询、聚合/join 与调用点，追踪来源 → 阶段 → 输出，标记未经验证的假设及越界位置。新建还须说明数据变化后的追加/刷新/幂等策略。细小操作不机械拆阶段，工具取自项目事实。

交付须使来源、输出、阶段及质量命题可映射到代码或明确的待实现契约；引用接口可在 CONCEPT 定位，缺失前提标未决。所属管道与 CONCEPT 共目录，跨概念管道放组合层；data boundary 用可核对接口名，供可选 hook 注入。发现模式只列候选，纯协调路由 sync。

读取接口可为拥有者公开的抽象状态关系或已声明 query；data boundary 写可定位的关系/接口名。写入仍通过声明动作，不能把跨概念私有表访问当作公开状态查询。
