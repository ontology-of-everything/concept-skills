# 协调规格（sync）

焦点：为达成应用目的，哪些已完成动作应引发哪些联动？SYNCS 记录独立概念间的因果规则；CONCEPT 定义局部行为，PIPELINE 描述数据质量。参数/授权遵循入口。

## 概念与命题

- **when** 匹配已完成动作及其输出，可取参数子集；多模式必须共同匹配同一因果 flow。
- **where** 经公开抽象状态或声明 query/条件产生零、一或多组绑定；零组不触发，也不自动产生错误或响应。
- **then** 对每组绑定调用声明动作，只使用已绑定值或常量；依赖未来输出须拆为下一条规则。
- **flow** 是外部事件引发的因果实例；`// flow:` 是文档职责分组。Requesting 表达请求入口，定时/消息可有自己的明确入口动作。

**应用目的** 说明整体要达成的结果，**概念目的** 说明局部价值；SYNCS 的组合选择须能解释应用场景如何达成结果，目的依据保存在总体 PRD。

核心命题：局部目的成立不保证整体成功。组合只选择概念允许的行为；调用公开接口仍须满足前置条件和并发契约。写动作原子维护自身不变量，where 查询不能代替它。

## 契约模板

使用 [统一规格模板](spec-format.md)，按其中的字段、结果分支和旧格式兼容规则核对。

## 提取与设计

1. 回填读处理器、索引/注册和调用点，映射触发 → 资格/绑定 → 动作及结果；顺序编排可对应多条规则。新建先核对应用目的、场景和参与概念契约；复杂分解交 software-concept-architect-design-cn。
2. 检查每个可达结果：响应、重试、补偿或有意忽略均须明确；需响应的入口覆盖成功与拒绝并关联 request/flow，后台可无响应。排除动作不能代替已调用动作的失败策略。
3. 检查并发实例隔离、重复触发/副作用及级联；循环需终止或受控持续运行依据，深度上限只属可选保护。缺联动按具体场景 tighten，自动化夺走控制则 loosen。
4. 将绕过抽象状态契约的直接 SQL/私有访问附文件位置，不能转录为合法规则。发现模式仅列候选；无跨概念协调的数据转换归 pipeline。

## 完成条件

每个 sync 包一份 SYNCS，按 flow 职责组织且共享规则身份唯一；触发、绑定、效果、失败和来源可追踪。报告规则数、应用场景覆盖、边界问题与未核实项；应用目的不明则标未决，不能从同步边猜测。迁移按入口整份保留语义；地图保留 when 合取、then 多目标及 where 查询边，hook 只列名不提取边界。
