# 原则、理由与正反例

按适用维度设计、审查或验证 CLI。检查点定义验收要求；实例说明证据，不规定通用语法。

## 十维检查

维度 1–3 对应可预测性，4–7 对应纵深防御，8–10 对应上下文效率。每行包含两项独立评分的检查。

| 维度 | 为什么 | 检查点 1 | 检查点 2 |
| --- | --- | --- | --- |
| 1. 契约 | 重复定义会漂移，过期交接产物会误导执行。 | 命令结构和命名一致。 | schema、校验和执行共用类型；可恢复产物绑定版本、目标、运行与输入摘要。 |
| 2. 输入 | 扁平快捷参数可能丢失嵌套结构，提示菜单会阻塞无头调用。 | JSON 保留嵌套类型；等价 flags 产生相同请求，并明确处理冲突。 | 支持完整非交互输入；缺参立即失败，并给出有效示例。 |
| 3. 结果 | 解析器需要稳定结构，受理不等于完成。 | 显式格式优先于 TTY 默认值；stdout 放机器数据，stderr 放诊断。 | 错误和退出码稳定；区分已受理、完成、失败和未知结果。 |
| 4. 校验 | Agent 输入不可信，结构看似合理不证明有效。 | 落实字段专属 schema 与 lint 约束，返回可修正的结构化错误。 | 落实路径、控制字符、ID、地址、重定向和编码边界，同时保留合法正文。 |
| 5. 认证 | 输入有效不能证明凭据和权限仍然有效。 | 使用凭据引用与最小权限；秘密不进入 argv、日志或普通配置。 | 服务端检查当前权限。 |
| 6. 变更 | 预演后到执行前，状态可能变化。 | 预演不写业务数据或持久恢复状态；声明认证及网络行为。 | 重新检查目标、授权和并发；高影响操作提供显式确认路径，同时保留已有授权。 |
| 7. 恢复 | 超时不等于失败，无界修复可能重复产生副作用。 | 同一意图重复执行只有一次持久业务效果，并按服务端保障验证。 | 安全重放前核对结果；限制修复次数和无进展循环，使过期报告失效并重跑受影响质量门。 |
| 8. 发现 | 内嵌手册会过期，完整展开 schema 消耗上下文。 | 每层 help 提供可执行示例。 | 查询当前机器可读的方法/类型 schema，限制引用展开并核对部署行为。 |
| 9. 响应 | 流式输出本身不能限制体积，也不能保证语义完整。 | 支持已声明的字段选择，说明裁剪发生在客户端还是服务端。 | 限制页数和记录大小，保留可解析的 JSON/NDJSON、游标、完整性状态及有意义的 null。 |
| 10. 知识 | 参数表不能指导决策，无关规则会分散注意力。 | description 说明对象、前置、直接影响和完成边界。 | 技能保留流程、约束与必要示例；按需加载参考、当前 help/schema 和任务产物。 |

## Human-first 与 Agent-first

人工便利功能不是缺陷。Agent-first 增加完整、稳定、无头的调用路径，并使用相同的校验与执行器。
下列 flags 和 JSON 形状仅为示意；使用时核对目标 CLI 的实际语法。

| 任务 | Human-first 正例 | Agent-first 正例 | 反例与后果 |
| --- | --- | --- | --- |
| 简单输入 | `--name invoices` 便于键入。 | 同一 flag 无交互执行，并映射为类型化请求。 | 仅因调用者是 Agent 就禁用所有 flags，增加无必要的复杂度。 |
| 嵌套输入 | 快捷参数覆盖常见单表场景。 | `{"sheets":[{"title":"Actual"},{"title":"Plan"}]}` 保留两张表。 | 重复 `--sheet-title` 覆盖第一张表；静默合并冲突的 flag/JSON 值。 |
| 输出 | 表格便于浏览。 | 显式 JSON 在任何终端都返回稳定 ID 和状态。 | 解析彩色列，或在 JSON 前打印进度，导致消费者失效。 |
| 缺参 | 显式交互模式提供 TTY 菜单。 | 返回字段路径、稳定错误码、有效调用及非零退出码。 | 等待已关闭的 stdin，或猜测生产环境，导致挂起或操作错误目标。 |
| 发现 | 聚焦的 help 提供有效用法。 | 只查询所需方法和引用类型。 | 每次提示词都复制完整手册，生成过期调用。 |
| 分页 | 人工逐页浏览表格。 | 达到页数上限时保留 `next_cursor` 和 `complete: false`，保留有意义的 `null`。 | 流式读取全部页、丢弃游标，或把 `{"owner":null}` 等同于缺少 owner。 |

对可比较的输入路径，比较归一化后的执行器请求，而非打印消息。
按方法契约保留省略、`null`、`false`、`0`、空字符串和数组的区别。
声明文件/stdin 语法，限制输入大小，每次调用只允许一个 stdin 消费者。

## 不可信输入加固（Untrusted input hardening）

Agent 生成的参数属于不可信输入：看似合理的字段和值仍可能违反契约。共用执行器按公开 API 的严格程度校验，覆盖 CLI 与 MCP 路径。
可本地判定的约束在业务请求或写入前检查；依赖状态的约束在变更前依据当前资源核对。

| 边界 | 正例规则与实例 | 反例 |
| --- | --- | --- |
| 路径 | 解析目标路径及父级符号链接，拒绝越出允许根目录的 `../../.ssh` 或符号链接逃逸。 | 只检查字面 `../` 子串，就认为目标仍在根目录内。 |
| 控制字符 | 标识符拒绝控制字符；展示正文时转义 `\u001b[2J` 等终端控制序列。保留正文契约允许的换行。 | 执行终端转义序列，或删除存储正文中的所有换行。 |
| 资源 ID | 拒绝将 `file_17?fields=name` 当成 ID；字段选择走声明的参数。URL/正文域允许带查询参数的 URL。 | 把 ID 直接拼进请求 URL，或对所有正文套用 ID 限制。 |
| 编码 | 声明接收原始值还是编码值。按消费者实际使用的形态校验，在传输边界只编码一次；存在解码时测试编码后的路径穿越。 | 反复解码直到看起来合法、盲目重复编码，或不分字段契约一律禁止 `%`。 |
| 未知字段 | 闭合对象对 `{"fon_size":12}` 返回字段错误；已声明扩展 map 保留用户键。 | 忽略编造字段、静默猜测纠错，或把所有动态 map 都封闭。 |
| 类型与边界 | 整数字段拒绝 `{"limit":"10"}`，除非已声明转换；三个元素的集合拒绝 `{"index":4}`。检查枚举及各类元素的限制。 | 接受一切语法合法的 JSON、静默截到边界值，或只靠提示词提醒。 |

将必需枚举、数值边界和质量阈值落实为可执行 schema 或 lint 契约。只执行已声明的约束，文字指令本身不提供保障。
错误返回稳定错误码、字段路径、允许值/范围和可执行的修正建议，并使用非零退出码。三个元素集合的错误示例：

```json
{"error":{"code":"INDEX_OUT_OF_RANGE","field":"index","expected":{"min":0,"max":2},"suggestion":"Select an index within the reported range"},"effects":"none"}
```

仅有证据证明时才返回 `effects: none`；诊断不回显秘密或危险控制字节。
预检拒绝后可修正重提；发送请求后超时应先核对结果，不能当成校验错误直接重试。

## 关键正反验证

在已授权的隔离夹具中运行。K1/K2 表示服务端支持的幂等键，B1/B2 表示不同正文。

| 场景 | 正例证据 | 反例 |
| --- | --- | --- |
| 输入预检 | 经每个支持的入口验证加固实例；本地非法输入不产生业务 HTTP 或写入，合法正文/map 仍通过。 | 只验证拒绝、不验证合法对照，或让 MCP 绕过 CLI 校验。 |
| 同一意图 | 两次提交 K1/B1，核对一次持久效果；有定义时核对原始 ID/回执。 | 每次重试生成新键。 |
| 新意图 / 正文冲突 | 另行授权的意图使用 K2；K1/B2 必须失败且无新增效果。重新检查当前权限和业务唯一性。 | 新操作复用 K1，或接受 K1 下变化的正文。 |
| 未知写入 | 先查询结果。仅在已验证的服务端 key 作用域和保留期内重放 K1/B1。无有效键时核对资源、回执和审计事实；否则保留 `unknown`。 | 把超时当成失败，重新发起写入。 |
| 纯本地预演 | 合法输入返回计划；非法 ID 或内联秘密在副作用前失败。核对业务 HTTP、凭据访问和恢复写入均为零。 | 声称纯本地，却初始化认证或发送业务请求。 |
| 秘密 / 外部正文 | 通过 stdin/私密文件注入测试秘密，检查全部格式和两个输出流。只脱敏秘密字段，保留公开 ID/类型和不可信文本来源。 | 错误泄露秘密、删除整个 token 对象，或执行返回正文里的指令。 |
| 异步完成 | HTTP 202 报告已受理；查询终态成功并确认所需结果。 | 仅凭任务 ID 就报告完成。 |
| 契约变化 | 对测试产物/版本重新核对当前 schema 与实际接受/拒绝的输入。 | 复用其他二进制的评分，或假定生成式 schema 已证明部署一致。 |

## 可恢复流程

需要重启恢复、人工检查或跨工具使用时才持久化交接产物。单步任务不必引入编排框架。
校验产物版本、目标、运行、输入摘要及允许的状态迁移；原子写入，并排除凭据。

```text
build -> check -> ready -> execute -> verify -> done
           |               |          |
           v               +----------+-> unknown -> reconcile
       needs_fix -> repair -> check
           |
           +-> blocked (budget exhausted or no progress)
```

正例：计划 A 改为 B 后，使受影响报告失效，重跑相关质量门；次数/时间预算耗尽或重复相同失败时停止。
内容与契约问题需要不同修复动作时，分别检查。反例：质量门失败后仍发布、B 沿用 A 的报告，或无限循环。
通过报告只证明该输入通过所列检查。文件、预演和客户端生成的 key 均不提供当前授权或服务端幂等保障。
