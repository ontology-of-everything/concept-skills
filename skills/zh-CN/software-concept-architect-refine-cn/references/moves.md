# 手法与证据

选择手法或解释坏味道前阅读本页。

| 手法 | 对象与权衡 |
| --- | --- |
| 拆分／合并（Split / merge） | 分离职责或组合不同概念；权衡简单性、控制权与能力。 |
| 统一／特化（Unify / specialize） | 统一同一主题的变体或形成专门变体；权衡通用性与需求贴合度。 |
| 收紧／放松（Tighten / loosen） | 增强或减弱概念间同步；权衡自动化与用户灵活性。 |

坏味道是假设，名称、大小或共享字段不足以证明过载或冗余。只有所需行为被排除时，
过窄才构成问题；特化可能合理。最小充分范围由根因决定，不按修改行数衡量。
沿用已有授权，只询问尚未解决的关键取舍；只读审查请求交付建议，不改文件。

每项选定改动说明场景与证据、含不改在内的备选、预期行为差异、受影响的契约与同步，
以及验证结果。区分设计推演与已执行测试。保持概念不变量，并检查应用层需求；
局部测试通过不证明整体适切。有意改变行为属于重新设计，不能声称是保持行为的代码重构。

  [Making Software Meaningful（让软件具有明确含义）](https://arxiv.org/abs/2606.11051)，2026-06-09 预印本：
