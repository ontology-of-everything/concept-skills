# Design sources

| Source | Used for |
| --- | --- |
| [Concept purposes](https://essenceofsoftware.com/posts/distillation/) | Applications may have several purposes; each concept has its own. Synchronization coordinates them. |
| [Jackson 2015, sections 8 and 9](https://groups.csail.mit.edu/sdg/pubs/2015/concept-essay.pdf) | Operational principles explain purpose; counterexamples test the argument. |
| [Beyond Objects, section 13](https://arxiv.org/abs/2606.27258) and [WYSIWID, section 4](https://arxiv.org/abs/2508.14511) | Concept specifications and causal synchronization, distinct from older transactional sync. |
| [Qualification](https://essenceofsoftware.com/tutorials/concept-basics/criteria/), [composition](https://essenceofsoftware.com/tutorials/concept-basics/sync/), [dependency](https://essenceofsoftware.com/tutorials/concept-basics/dependency/) | Eight criteria, missing/excessive coordination, intrinsic/extrinsic dependencies, and subsets. |
| [Design moves](https://essenceofsoftware.com/posts/design-moves/) and [course rubric](https://61040-fa25.github.io/resources/concept-rubric) | Split/merge, unify/specialize, tighten/loosen; application notes. |

[The local contract](spec-format.md) defines notation and labeled query/entry extensions to WYSIWID v1.
The workflow, alignment sections, purpose arguments, and rule-node diagram are repository conventions.
An operational principle explains a representative result; neither it nor its argument proves every behavior.
