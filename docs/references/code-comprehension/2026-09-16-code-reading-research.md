# 阅读代码：从研究到可执行练习

核验日期：2026-09-16。范围：代码阅读与程序理解的一手论文、作者网站和出版社预览。沿用仓库 `docs/references/<主题>/<日期>-<主题>-research.md` 的研究笔记惯例；未修改技能。

## 核心判断

阅读代码的目标可以设为：建立足以解释行为、预测变化并定位证据的模型。这个表述是本文综合建议，不是某项实验验证的唯一最佳方法。逐行翻译、记住目录和看懂 AI 的摘要，均不足以单独验证理解。

## 一轮 30 分钟的阅读流程

下面是结合以上材料的工程建议；时间分配是练习约定。

1. **3 分钟：选定问题。** 写下“输入 X 后，系统为何得到 Y？”或“修改规则 Z 会影响哪里？”。同时写成功的证据标准，例如找到状态写入点并解释拒绝条件。
2. **5 分钟：找锚点。** 从测试、公开接口、错误消息或领域术语定位相关入口。先记录模块职责假设，不为画完整目录图而遍历仓库。
3. **8 分钟：跟一条实际路径。** 用具体输入沿调用与数据变化前进。记下输入、分支、状态变化、返回值和外部副作用；在与问题无关的调用处暂时停下。
4. **5 分钟：压缩成语义块。** 把代码分成“检查资格—占用资源—保存结果”等动作。每块说明前置条件、结果和失败方式；名称只是线索，需回到实现核验。
5. **5 分钟：主动找反例。** 换为空值、边界值、重复调用或失败输入；按实际问题决定是否检查并发。先预测，再用测试、调试或受控运行核验。一次运行只能覆盖其执行路径。
6. **4 分钟：脱离代码复述。** 写出目的、状态、约束、主要路径、失败路径以及仍不确定的点。解释每个关键结论的代码或测试依据。

示意笔记：

```text
问题：
当前假设：
证据：文件 / 符号 / 测试
实际路径：输入 → 判断 → 状态改变 → 输出或副作用
反例：
预测与实际是否一致：
仍未知：
下一步只查：
```

## 如何练出能力

- 选一段可完整讨论的小代码，独立圈出变量及其使用位置，连接调用，再选最关键的五行，解释理由。这是对 Code Reading Club 练习的简化应用。
- 用一句话解释一块代码的业务作用，随后指出维持这句话成立的条件。若只能复述语法，继续寻找输入、状态和调用方。
- 画图时按问题选择：控制流用于解释分支，数据流用于解释值的来源，状态图用于解释合法转换。绘图选择是工程建议，不是上述论文的统一规定。
- 让 AI 提供带文件和符号依据的导航候选、反例与测验题；自己先预测行为，再核对解释。此项是面向 AI 编程的应用建议，本文所列研究没有直接验证这套 AI 协作流程。

## 建议阅读顺序

先做 Code Reading Club 练习，再读《The Programmer’s Brain》第 2、4 章；随后读 Sillito 论文的问题分类。若主要审查 AI 生成的修改，再读 2025 年审查理解论文。Wyrich 的概念框架适合继续追问“如何证明我理解了”。Spinellis 的书适合长期配合实际开源代码练习。

局限：本次是有范围的来源核验与方法综合，并非系统文献综述，也未对练习做效果实验。不把旧工具环境下的观察机械推广成现代 IDE 或 AI Agent 的定律。
