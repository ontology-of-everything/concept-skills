# 概念框架学习（Learning with Conceptual Frameworks）

围绕自己的学习目标构建可复用的知识体系。先做目标定性，建立关键框架，再将不同来源的方法、误区、案例吸收为概念下的知识。支持自动匹配与显式调用。

```text
$learning-concept-framework-cn 帮我用成熟框架学习销售，并吸收这些笔记。
```

## 选择规则

按用户要求的结果判别，不按“概念”关键词匹配：

| 要求的结果 | 路由 |
| --- | --- |
| 学习新领域，先明确目标与关键框架 | 本技能：形成初始框架 |
| 将多本书、课程、文章整合为知识体系 | 本技能：按概念吸收知识 |
| 将按作者目录摘抄的笔记重构为知识树 | 本技能：按学习目标重新组织 |
| 按原文结构概括资料 | 普通摘要 |
| 从原文抽取场景、概念、实体 YAML | `semantic-pkm-creator` |
| 设计软件概念、状态、动作与同步 | `concept-design` |

## 产物

交付 `learning-framework-<topic>.md`，包含四部分：

| 部分 | 必须回答 |
| --- | --- |
| 目标与定性 | 要解决什么问题？怎样算学会？问题属于什么性质，由哪些概念及关系决定？ |
| 关键框架 | 概念各指什么、如何关联、为何有助于目标？复用了什么框架、为何调整？目标覆盖是否完备、证据是否支持？ |
| 知识树 | 以目标为根、核心概念为主干、知识为叶；每条知识附出处、归属理由，区分证据与推断。 |
| 缺口 | 哪些关系或结论尚待验证？下一步需要学习什么？ |

无资料时先交付待验证框架，保留空分支；有资料时填入有出处的知识。完备性相对于当前目标判断，不要求穷尽领域；正确性接受证据和反例检验。

## 目标定性示例

“学习销售”只是主题。若目标是“能解释客户为什么购买或拒绝，并选择下一步行动”，可评估价值、信任、竞争是否构成适用的关键框架。这只是候选框架，须按实际目标与材料验证。

```text
解释购买或拒绝，选择下一步行动
├─ 价值：客户所得与付出
│  └─ 资料中有关需求和收益的方法或误区［出处、归属理由］
├─ 信任：客户对承诺与兑现的判断
│  └─ 资料中有关承诺和证据的方法或误区［出处、归属理由］
└─ 竞争：客户考虑的替代选择
   └─ 资料中有关替代方案的方法或误区［出处、归属理由］
```

“三大误区”是作者的表达结构，不直接决定知识树的主干。“六经注我”指用自己的问题组织学习；资料中的反证仍可修正框架，不能为维护框架而扭曲原意。
