# 概念框架学习（Learning with Conceptual Frameworks）

围绕学习者的目标建立模型树。“目标定性”就是立关键框架：判断达成目标所需的核心因素及其关系，再把资料中的方法、误区、案例归入框架。支持自动匹配与显式调用。

```text
$learning-concept-framework-cn 帮我用成熟框架学习销售，并吸收这些笔记。
```

## 选择规则

按用户要求的结果判别，不按“概念”关键词匹配：

| 要求的结果 | 路由 |
| --- | --- |
| 学习新领域，先明确目标与关键框架 | 本技能：形成初始框架 |
| 将多本书、课程、文章整合为知识体系 | 本技能：按概念吸收知识 |
| 将按作者目录摘抄的笔记重构为知识树 | 本技能：按学习目标重新组织 |
| 按原文结构概括资料 | 普通摘要 |
| 从原文抽取场景、概念、实体 YAML | `semantic-pkm-creator` |
| 设计软件概念、状态、动作与同步 | `concept-design` |

## 产物

交付 `learning-framework-<topic>.md`，保留四个可追溯的层次：

| 部分 | 必须回答 |
| --- | --- |
| 目标 | 要解决什么问题？怎样算达标？ |
| 目标定性／关键框架 | 实现目标需要哪些因素及关系？为何选这个框架？给定资料如何支持或反驳它，是否覆盖目标？ |
| 概念与关系 | 框架下各概念起什么作用、怎样互相影响？注明资料依据或推断。 |
| 有出处的知识 | 方法、误区、案例归于哪个概念，为什么？原文或其他来源是什么？ |

若原文已有适配框架，可复用并说明其怎样实现目标；但原文目录本身不自动成为模型树主干。对每个框架分支都要查给定资料，标出支持、反证或缺口。完备性相对于当前目标判断，正确性接受证据和反例检验。

## 目标定性示例

“学习销售”只是主题。若目标是“能解释客户为什么购买或拒绝，并选择下一步行动”，可评估价值、信任、竞争是否构成适用的关键框架。这只是候选框架，须按实际目标与材料验证。

```text
目标：解释购买或拒绝，并选择下一步行动
└─ 目标定性／关键框架：购买是多因素选择；价值、信任、竞争共同解释选择［候选，须由给定资料检验］
   ├─ 概念：价值——客户所得与付出
   │  └─ 相关方法或误区［出处、归属理由］
   ├─ 概念：信任——客户对承诺兑现的判断
   │  └─ 相关方法或误区［出处、归属理由］
   ├─ 概念：竞争——客户考虑的替代选择
   │  └─ 相关方法或误区［出处、归属理由］
   └─ 关系：价值与替代选项相比较；信任影响承诺能否被接受［待资料检验］
```

“三大误区”是作者的表达结构，不直接决定知识树的主干。“六经注我”指用自己的问题组织学习；资料中的反证仍可修正框架，不能为维护框架而扭曲原意。
